# Identity Model

## Overview
Earthlings uses a **decentralized, non-custodial identity model**
based on cryptographic proof of wallet ownership and SBT passports.

## Identity layers

### 1. Wallet
- Cryptographic keypair owned by the user
- Used for authentication (signing nonces)
- One user can link multiple wallets
- Exactly one primary wallet at a time

### 2. User (internal)
- UUID generated by the platform
- Bound to one or more wallets
- Has no inherent personal meaning
- Serves as stable internal identifier

### 3. SBT Passport
- Non-transferable token
- Proves verified membership
- Contains no personal data
- Can be revoked

## Authentication flow
1. User requests nonce
2. User signs nonce with wallet
3. Backend verifies signature
4. Session is created
5. RLS context is set for all DB queries

## Authorization
- Authorization is NOT stored in the wallet
- All permissions derived from:
  - cell membership
  - roles (coordinator, facilitator)
  - project relationships

## Why not DID (yet)
- DID adds complexity without clear MVP benefit
- Wallet + SBT already satisfies:
  - uniqueness
  - non-transferability
  - verifiability

DID compatibility can be added later without breaking this model.

## Security guarantees
- Platform cannot impersonate user
- Identity cannot be transferred or sold
- Loss of wallet = loss of access (by design)
- Revocation is explicit and auditable
